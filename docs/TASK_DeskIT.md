# TASK_DeskIT —— 原子任务分解（步骤 2 ~ 步骤 9）

> 步骤 1（工程骨架）、步骤 2（M1 便携启动）、步骤 3（M2 设备识别与信息采集）、步骤 4（M3 问题诊断）与步骤 5（M4 修复动作库）已完成。以下每个步骤**独立可编译、可测试**，且**每步一次提交并推送 master**，提交信息使用中文。

## 步骤 2 —— M1 便携启动与运行环境（已完成）
- **目标**：实现启动自检（程序哈希、数据目录可读写、可用空间、系统版本、当前权限、实例互斥）与提权/只读回退。
- **产出**：`DeskIT.Windows` 提权与自检实现、`DeskIT.App` 启动页三块（自检结果 / 权限与提权入口 / 能力摘要）。
- **验收要点**：能正确检测管理员令牌；取消提权即回退只读模式且如实提示；空间 <200 MB 不开始新会话、<500 MB 提示归档。
- **依赖**：步骤 1。

## 步骤 3 —— M2 设备识别与信息采集（已完成）
- **目标**：采集系统版本、硬件摘要、已装软件清单、网络配置，形成设备档案快照。
- **产出**：采集器实现与快照模型落地；机器标识（硬件序列号优先，缺失回退“主机名 + 首次采集时间”）。
- **验收要点**：基础采集 ≤60 s；多次采集生成独立快照并保留历史；同一机器归并到同一档案。
- **依赖**：步骤 2。
- **实际落地**：Core 新增 `CollectionModels.cs` / `CollectionRules.cs` / `MachineIdentityRules.cs`（分组、字段状态四类归因、快照保留 5 份、标识回退与档案归并，共补 15 项单测）；Windows 新增 `WmiQuery.cs` / `WindowsProbes.cs` / `WindowsCollectionItems.cs`（7 组只读采集：WMI、注册表、网络接口、卷信息、固定参数 netsh 查询）/ `DeviceInfoCollector.cs`（分组并行 + 组内串行 + 单项超时）/ `SnapshotStore.cs`（`data\snapshots\<机器>\`）/ `DeviceCollectionService.cs`；App 新增“设备信息采集（M2）”页。
- **实测**：本机基础采集 5.9 秒，29 个采集项全部执行；序列号为占位串时正确回退为“主机名 + 首次采集时间”；连续 7 次采集归并同一档案且档案内快照恰为 5 份。

## 步骤 4 —— M3 问题诊断（已完成）
- **目标**：场景化诊断项，输出 正常/异常/提示/未知 四态；无法判定记“未知”。
- **产出**：规则化诊断项与引擎；诊断会话状态机接线。
- **验收要点**：每个诊断项可独立执行；结论只落在四态内；采集与诊断期间界面保持可操作。
- **依赖**：步骤 3（采集数据）、Core 诊断结论/状态机。
- **实际落地**：Core 新增 `DiagnosisModels.cs` / `DiagnosisRules.cs`（诊断结论四态、场景/会话模型、异常置顶排序、四态统计、会话标识、文案）与 `SessionStateRules.cs`（终态封闭、合法迁移、结论映射，共补 12 项单测）；Windows 新增 `PowerShell51Executor.cs`（PS 5.1 `-EncodedCommand` + 200 行截断 + 整进程树超时终止）、`WindowsDiagnosisItems.cs`（7 场景 38 个只读诊断项）/ `ProblemDiagnoser.cs`（场景并行 + 场景内串行 + 单项独立超时 + 只读提权项标记未执行）/ `DiagnosisStore.cs`（`data\sessions\<会话>.json`）/ `ProblemDiagnosisService.cs`（新建 → 诊断中 → 已结束 状态机接线）；App 新增“问题诊断（M3）”页。
- **实测**：本机全场景诊断 17.9 秒，38 个诊断项全部执行、2 项因只读标记未执行；异常置顶排序、四态统计与会话落盘均正确（会话文件 `data\sessions\sess-*.json` 生成）。修复了 `software.unresponsive` 使用不存在的 `Win32_Process.Responding` 导致的无效查询（改用 PowerShell `Get-Process.Responding`），并修正命令行工具输出解码（按 OEM 代码页解码，避免 `powercfg` / `net accounts` 中文输出乱码）。

## 步骤 5 —— M4 修复动作库（已完成）
- **目标**：声明式动作定义（风险级别、需重启、可回滚、前置条件、脚本入口）与统一执行器。
- **产出**：`actions/` 定义加载、执行器（超时/取消/输出截断/结果归类）、回滚信息写入加密备份区。
- **验收要点**：排序遵循“按风险升序、需重启排最后”；高风险动作二次确认；只读模式下全部禁用。
- **依赖**：步骤 2、步骤 3（PS 5.1 执行器）。
- **实际落地**：Core 新增 `ActionModels.cs`（动作定义/参数/前置条件/确认方式/执行结果/备份记录模型）、`ActionRules.cs`（风险分级与确认要求、结果归类、参数缺失校验、占位符提取与转义绑定、前置条件判定、无来源占位符识别）与 `ActionOrdering.cs`（风险升序 + 需重启排最后），共补 20 项单测；Windows 新增 `ActionLibrary.cs`（读取 `actions/*.json` 并按定义问题清单校验）、`ActionPreconditionChecker.cs`（路径存在 / 服务存在，无法判定按满足处理）、`ActionBackupStore.cs`（`data\backup\actions\<执行标识>.json`）、`ActionExecutor.cs`（权限与前置条件 → 参数解析与绑定 → `Wrap` 退出码约定 → 超时/取消/截断/归类 → 审计与回滚信息落盘）；新增 `actions/` 下 7 个定义文件共 **29 个动作**；App 新增“修复动作（M4）”页（搜索、按风险排序清单、参数填写、风险与需重启徽标、只读禁用原因、高风险逐项二次确认、不可逆输入确认词、汇总确认、执行结果展示、中止后续动作），并把诊断建议动作标识映射为“动作名称（标识）”。
- **实测**：`dotnet build -c Release` 0 警告 0 错误、`dotnet test` 59 项全绿（动作相关 20 项）；29 个动作定义加载 0 问题、PowerShell 语法 0 错误；排序满足“低→中→高→不可逆、需重启排最后”；执行器归类正确（成功 / 失败 / 只读跳过 / 缺参跳过 / 带参成功 / 成功需重启）；备份区按执行记录正常落盘；对齐了诊断建议与动作定义的 `startup.trim-startup-items` 标识；应用启动冒烟测试通过（XAML 解析无误、进程存活）。

## 步骤 6 —— M5 软件安装与卸载 + M6 账号与权限辅助（已完成）
- **目标**：U 盘携带的 `packages/` 包的安装/卸载（含哈希校验与静默参数）；账号与权限查询类辅助。
- **产出**：包描述解析与校验、复用 M4 执行器执行；查询类只读辅助。
- **验收要点**：来源不可验证的包默认禁止执行；完整性校验失败即拒绝；查询类不产生变更。
- **依赖**：步骤 5。
- **实际落地**：Core 新增 `PackageModels.cs`（架构/完整性/匹配状态/操作类型/安装器归因/包描述/已装条目/预检/操作上下文与结果模型）、`PackageRules.cs`（完整性判定与处置说明、架构与磁盘空间检查、版本比较、已装匹配、退出码归因、`BuildOperationAction` 把“包的一次操作”转为 M4 动作定义、`BuildScript`、`FormatBytes`）、`AccountModels.cs`（本地账号信息、快照/摘要/密码策略/UAC 描述模型）与 `AccountRules.cs`（账号状态与从未登录判定、摘要统计、`net accounts` 策略解析、UAC 风险描述），共补 35 项单测；Windows 新增 `PackageLibrary.cs`（加载 `packages/*.json`、路径越界检查、SHA-256 校验）、`PackageService.cs`（已装软件读取 + 预检 + 调用 M4 执行器 + 事后版本复读与残留说明）、`AccountDirectoryQuery.cs`（单条 PowerShell 5.1 脚本输出 JSON，只读呈现账号/管理员组/共享凭据/密码策略/UAC/时间源等事实）；`WindowsCollectionItems.cs` 的软件条目补充 `UninstallString`；新增 `packages/example-7zip.json` 示例包描述，`actions/account.json` 追加 4 个账号变更动作（解锁 / 启用 / 停用 / 重命名），变更类动作自动复用 M4 的二次确认与备份审计；App 新增“软件安装卸载（M5）”页（包清单 / 已装软件可搜索 / 操作与结果三列，预检阻断与提示可视化）与“账号与权限（M6）”页（账号清单 / 管理员组 / 环境事实 / 共享凭据四列），并新增 4 个状态色转换器。
- **实测**：`dotnet build -c Release` 0 警告 0 错误、`dotnet test` **94 项全绿**；`actions/account.json` 全部 6 个动作脚本通过 PowerShell Parser 语法校验；`packages/example-7zip.json` 可正常解析并随构建复制到输出目录 `packages/`。

## 步骤 7 —— M7 记录与多机台账
- **目标**：单全量台账归并、处理记录（自动带处理人工号 + 姓名）、会话结束后静默产出脱敏自包含报告。
- **产出**：`ledger.db` 读写、`reports/` 报告生成（HTML + Markdown）、记录仅追加。
- **验收要点**：同一机器归并同一档案；报告双击可离线打开；脱敏规则生效（姓名遮蔽、工号保留）。
- **依赖**：步骤 4、步骤 5。

## 步骤 8 —— M8 介质安全与数据保护
- **目标**：主密码派生密钥加密数据目录、介质可写性探测、拔出保护、介质迁移。
- **产出**：加密存储（AES-256-GCM 或等价）、探测与拔出保护流程、`operators.json` 登记。
- **验收要点**：明文不落盘；主密码错误不可读台账；不使用机器绑定保护机制；探测失败触发保护流程。
- **依赖**：步骤 7。

## 步骤 9 —— M9 受控自定义命令与动作沉淀
- **目标**：管理员 + 高级模式 + 逐条确认 + 强制记录的自定义命令入口，并可将命令另存为正式修复动作。
- **产出**：命令执行与记录（命令文本脱敏、退出码、耗时）、高级模式开关（介质级记住，开启需主密码 + 二次确认）。
- **验收要点**：不提供“不记录执行”路径；开关变化写入审计事件；沉淀动作进入 `actions/` 后可复用。
- **依赖**：步骤 5、步骤 7、步骤 8。
